# QuantFund V8 Foundation: Comprehensive Modular Implementation Plan

## Context

QuantFund V8 is a multi-strategy quantitative trading platform (200-400 US equities, hourly-to-daily rebalancing). The system has 17 implemented subsystems across 169 Python modules with 170 test files. However, it currently operates as a **market-hours-only two-process model** (`main_run.py` for live trading, `train_pipeline.py` for offline training). This plan transforms it into a **professional always-on 24/7 system** with a single master orchestrator handling trading, training, maintenance, and everything in between. It also addresses test infrastructure rot, documentation sprawl, and code organization debt.

**Problems being solved:**
1. No unified orchestrator -- training, data ingestion, and maintenance are separate manual processes
2. CI/CD tests are broken -- nightly runs redundant tests, ~69 test files lack tier markers, unused markers exist
3. Documentation scattered across 3 large .md files (HANDOFF.md, TESTING_PLAN.md, PLAN.md) with no single README
4. Code organization debt -- `trading_engine.py` is 1,200+ lines, `main_run.py` is 740+ lines with embedded classes
5. No pre-market, post-market, overnight, or weekend automation

### Step 1.2 -- Fix nightly.yml redundancy

**Problem:** `nightly.yml` runs `pytest tests/ -m "not tier5"` (which already collects benchmark, stress, and regression tests), then re-runs benchmarks, stress, and regression explicitly -- doubling execution time.

**Fix:** Remove the 3 redundant steps. Single command:
```yaml
- name: Run all tests except weekly
  run: pytest tests/ -m "not tier5" -q --timeout=300
```

File: `.github/workflows/nightly.yml`

### Step 1.3 -- Fix PR gate coverage inconsistency

**Problem:** `pr-gate.yml` line 31 runs `pytest tests/ --cov=quant_fund --cov-fail-under=85` without a marker filter, running the entire test suite on every PR (not just tier1+tier2).

**Fix:** Add marker filter to coverage run:
```yaml
- run: pytest tests/ -m "tier1 or tier2" --cov=quant_fund --cov-fail-under=85 --cov-report=term-missing
```

File: `.github/workflows/pr-gate.yml`

### Step 1.4 -- Remove unused "slow" marker, enhance pytest config

- Remove `slow` marker from `pyproject.toml` (defined but never used in any test file)
- Add `timeout = 120` default per-test timeout
- Add `pytest-timeout` and `pytest-xdist` to `requirements.txt`

File: `pyproject.toml`, `requirements.txt`

### Step 1.5 -- Verify all markers are accounted for

Run `pytest --collect-only -m tierN` for each tier (1-5) and confirm every test is classified. Report any gaps.

## Phase 3: Code Refactor and Reorganization

> Clean up module boundaries, eliminate duplication, reduce file sizes.

### Step 3.1 -- Decompose `trading_engine.py` (1,206 lines)

Extract focused modules from the monolithic orchestrator:

| New Module | Extracted From | Responsibility |
|-----------|---------------|----------------|
| `quant_fund/main/convergence_loop.py` | `_convergence_tick` + capacity/risk gating | Order convergence logic (~200 lines) |
| `quant_fund/main/research_optimizer.py` | `_run_research_and_optimize` chain | Research -> optimize pipeline (~140 lines) |
| `quant_fund/main/engine_health.py` | Health checks, reconciliation, snapshots | Operational health (~200 lines) |

`TradingEngine` becomes a thin orchestrator (~400 lines) that delegates to these modules.

### Step 3.2 -- Decompose `main_run.py` (740 lines)

- Move `YFinanceFeedProvider` class -> `quant_fund/data_layer/connectors/yfinance_feed_provider.py`
- Move `bars_to_market_data` utility -> `quant_fund/data_layer/market_data_utils.py`
- `main_run.py` becomes a thin CLI wrapper (~200 lines)

### Step 3.3 -- Eliminate duplicate risk gate logic

`_convergence_tick` has two parallel code paths: one using `RiskCascadeCoordinator` and a fallback that inlines the same logic. Remove the fallback -- if no coordinator is configured, create a default one from available risk components.

### Step 3.4 -- Deprecate superseded runners

`paper_trading_runner.py` and `live_trading_runner.py` in `quant_fund/main/` duplicate functionality now in `TradingEngine`. Add deprecation warnings; plan removal in Phase 4.

### Step 3.5 -- Standardize config injection

Many components do `cfg = config or {}` + `cfg.get("key", default)`. Create `quant_fund/config/typed_config.py` with dataclasses for each subsystem's config to prevent typo bugs and enable IDE autocomplete.

## Phase 4: Always-On System Architecture

> Transform the system from a market-hours trading loop into a 24/7 orchestrator handling all operational phases.

### Step 4.1 -- Extend SystemStateMachine with operational phases

Add new states to `quant_fund/infrastructure/system_state_machine.py`:

```
Current:  INITIALIZING -> DATA_READY -> TRADING_ENABLED -> RISK_HALT -> SHUTDOWN

Extended: INITIALIZING -> PRE_MARKET -> DATA_READY -> TRADING_ENABLED -> POST_MARKET -> OVERNIGHT -> WEEKEND_MAINTENANCE
          (+ RISK_HALT and SHUTDOWN reachable from any state)
```

New states:
- `PRE_MARKET` -- data refresh, model warm-up, broker connectivity check, position reconciliation
- `POST_MARKET` -- EOD P&L, trade reporting, fill quality analysis, final reconciliation
- `OVERNIGHT` -- model training, alt data ingestion, data quality checks, stress tests, backups
- `WEEKEND_MAINTENANCE` -- full data rebuild, deep diagnostics, DB maintenance, governance reviews

### Step 4.2 -- Build MasterScheduler

Create `quant_fund/main/master_scheduler.py`:

- Maintains NYSE trading calendar (holidays, early closes)
- Automatically transitions between operational phases:
  ```
  04:00 ET  -> PRE_MARKET (data refresh, model warm-up, broker check)
  09:25 ET  -> DATA_READY (readiness checks)
  09:30 ET  -> TRADING_ENABLED (live trading)
  16:00 ET  -> POST_MARKET (settlement, EOD reporting)
  17:30 ET  -> OVERNIGHT (training, ingestion, maintenance)
  04:00 ET  -> PRE_MARKET (next day cycle)
  ```
- Handles holidays (skip trading, run maintenance)
- Handles weekends (WEEKEND_MAINTENANCE on Saturday/Sunday)
- Integrates with existing `IngestionScheduler` in `infrastructure/ingestion_scheduler.py`

### Step 4.3 -- Absorb train_pipeline.py into overnight phase

Create `quant_fund/main/phases/overnight.py`:
- Runs the full ML training pipeline (reusing existing `DataBuilder`, `PromotionGate`)
- Ingests alternative data (news, options, macro, analyst, ETF -- using existing `alternative_data/` modules)
- Runs data quality checks on ingested data
- Updates factor risk model
- Runs stress tests (using existing `stress_test_engine.py`)
- Generates disaster recovery backup (using existing `disaster_recovery_manager.py`)
- Runs data version control snapshot (using existing `dataset_version_control.py`)

`train_pipeline.py` remains as a standalone CLI for manual/ad-hoc runs.

### Step 4.4 -- Implement pre-market phase

Create `quant_fund/main/phases/pre_market.py`:
- Refresh overnight data (corporate actions, dividends, splits)
- Download pre-market quotes
- Verify broker connectivity and account status
- Reconcile positions against broker
- Warm up ML models (run prediction on yesterday's data)
- Validate data feed health
- Check for config changes
- Report readiness status

### Step 4.5 -- Implement post-market phase

Create `quant_fund/main/phases/post_market.py`:
- Calculate end-of-day P&L
- Generate trade report (using existing `TradeRecorder`)
- Run fill quality analysis (using existing `ExecutionQualityMonitor`)
- Full position reconciliation with broker
- Save comprehensive state snapshot
- Publish EOD summary alerts
- Calculate performance attribution
- Update alpha monitoring metrics

### Step 4.6 -- Implement weekend maintenance phase

Create `quant_fund/main/phases/weekend_maintenance.py`:
- Full historical data rebuild and validation
- Deep model diagnostics (feature importance drift, prediction distribution)
- Database maintenance (SQLite VACUUM, WAL checkpoint)
- Full reconciliation with all data sources
- Generate weekly performance report
- Run governance review checks (using existing `governance/` module)
- Archive old logs, clean temp files
- Verify disaster recovery integrity

### Step 4.7 -- Enhance emergency handling

Enhance `quant_fund/infrastructure/disaster_recovery_manager.py`:
- Add actual backup execution (SQLite copy, config snapshot)
- Automatic recovery from common failures (broker disconnect via existing `broker_reconnection_manager.py`, data feed failover)
- Heartbeat monitoring -- detect incomplete shutdowns via stale lock file
- Graceful degradation modes:
  - Broker disconnect: pause convergence, keep monitoring, auto-reconnect
  - Data feed failure: use cached data, alert, degrade to read-only
  - Model corruption: fall back to equal-weight or last-known-good weights

### Step 4.8 -- Update main_run.py integration

- Remove market hours enforcement from CLI level (MasterScheduler handles it)
- Add `--mode paper|live|backtest|debug` flag
- Engine starts and stays running, cycling through phases automatically
